最近整理博客的时候翻到了去年这个时候的截图，发现主题已经换到第三个了。一年三次，听起来很折腾，但每一次都不是冲动。

这篇文章想认真聊聊这一年的主题折腾史。不是为了证明哪个主题最好，而是想分享一个普通博客主在「性能」「颜值」「维护成本」三个维度之间反复横跳的真实过程。

## 一、起点：Hugo + Ananke（2025 春）

最初选择 Ananke 是因为它是 Hugo 官方推荐的主题——开箱即用、文档全、稳定性好。作为一个刚把博客从 Hexo 迁到 Hugo 的新人，我需要的是「能跑起来」而不是「能跑得漂亮」。

前三个月，Ananke 完美胜任：

- ✅ 默认主题就够用，不需要任何定制
- ✅ `hugo.toml` 里改几个参数就能调颜色、字体、布局
- ✅ 移动端响应式默认就做好了
- ✅ Hugo 升级时几乎不会破（兼容性好）

但慢慢开始觉得少了点什么。

> Ananke 像一件优衣库的基础款 T 恤——永远不会出错，但也永远不会让人惊艳。

最让我不舒服的是首页：所有文章以卡片形式平铺，没有视觉层级，第一眼看上去像「文档列表」而不是「博客」。

## 二、转折：尝试 PaperMod（2025 秋）

第一次换主题是在博客写到第 50 篇的时候。偶然看到了 PaperMod 的演示站，瞬间被那种「克制的高级感」击中：黑白灰配色、克制的留白、恰到好处的卡片阴影。

迁移过程比我想象的简单——PaperMod 提供了 `exampleSite`，把所有配置项都写好了。基本上就是复制粘贴配置 + 复制 `assets/css/extended/` 来自定义样式。

但用了一个月后，我发现几个问题：

1. **搜索功能依赖 Fuse.js**，部署到 Cloudflare Pages 时偶尔触发 worker 超时
2. **归档页（archives）默认样式**和我的内容不太搭，需要深度定制
3. **暗色模式**默认是「亮度对换」，不够精致

最致命的是第三个。我的暗色模式只是把所有白色背景反相成黑色，但很多链接色、强调色在暗色下变得不协调。

## 三、二次改造：在 PaperMod 基础上做减法（2026 初）

第二次换主题不是「换」，而是「深度改造」。我把 PaperMod 的所有 `assets/css/` 重写了一遍，但保留了它的目录结构和 partial 模板。

具体做了什么：

| 维度 | PaperMod 默认 | 我的改造 |
|------|--------------|----------|
| 字体 | 默认无衬线 | Source Serif 4（标题）+ Inter（正文） |
| 主色 | 蓝色（#3273dc） | 珊瑚橙（#FF6E40） |
| 卡片样式 | 阴影 + 圆角 | 浅边框 + 微抬升 |
| 文章正文 | 18px 无衬线 | 18px 衬线，行高 1.75 |
| 暗色模式 | 颜色对换 | 自定义 token，亮度提升一档 |
| 首页 | 卡片平铺 | Hero + 编辑精选 + 最新文章 |
| TOC | 顶部小目录 | 侧边 sticky 目录 + 阅读进度 |

这一步花了我整整两周，但效果立竿见影。博客的气质从「极客博客」变成了「编辑博客」，订阅增长率也跟着提升了 30%。

## 四、最终的答案：完全继承但视觉层完全重写（2026 夏）

第三次调整不是换主题，而是接受了**「PaperMod 是个优秀的架构，不是优秀的设计」**这个事实。

现在的方案：

```toml
# hugo.toml 关键配置
[params]
  ShowReadingTime = false    # 我们自己算
  ShowShareButtons = false   # 我们自己实现
  ShowBreadCrumbs = false    # 我们自己实现
  profileMode = false        # 不要 PaperMod 那种 Profile 模式
  socialIcons = []           # 我们用 SVG 自己实现
  homeInfoParams = ""        # 关闭 PaperMod 的 hero 信息
```

具体做法是：

1. **继承 PaperMod 的 i18n、shortcode、SEO defaults、syntax highlight**——这些基础设施它做得很成熟，没必要重造
2. **完全重写 `layouts/_partials/header.html` 和 `footer.html`**——头部导航和页脚是用户停留最久的区域，必须用自己的设计
3. **完全重写 `layouts/index.html` 和 `_default/single.html`**——首页和文章详情是博客的「门脸」，必须用编辑设计的思路重做
4. **完全覆盖 `assets/css/extended/custom.css`**——所有颜色变量、组件样式都用自己的 token 系统

结果如何？

- 构建速度：完全没变（Hugo 自己的事，与主题无关）
- 维护成本：比纯 PaperMod 高一些，但远低于完全自建
- 视觉差异化：100% 不会被认成 PaperMod

## 五、给同样在纠结主题的你

如果你刚开始写博客，我建议：

1. **前 20 篇文章用 Ananke 或 PaperMod**——把时间花在写内容上，而不是调主题
2. **20-100 篇之间开始定制**——这时候你对自己的内容形态有了清晰认知
3. **100 篇以上考虑深度改造或自建**——你需要的可能不再是「主题」，而是「定制系统」

主题不是越新越好。最适合你的主题是那个「让你忘记它在」的主题。

## 结语

这一年的折腾让我明白一个道理：**主题是手段，不是目的**。博客的核心是内容，主题只是让内容呈现得更舒服的容器。

如果你也在换主题的路上，希望这篇文章能给你一些参考。如果你已经有了一个不错的主题，那就别折腾了，回去写下一篇吧。
